# v2 job P0-server: setup works out of the box; one bad event can never stop ingest
Worktree: /home/pal/github/supermetry-mono/supermetry-wt/p0-server (branch v2/p0-server).

1. Config (verified bug): `internal/config/config.go:18` defaults Listen to `:8080` while Makefile DEV_DEFAULTS, `.env.example`, Dockerfile, deploy/docker-compose.yml, installer and deploy/README use 8787. `make dev` sets only SUPERMETRY_BASE_URL=http://localhost:8787, so the server listens on :8080 and the Origin check (`internal/platform/http/private.go` ~582-617) 403s every setup/login POST. Fix: default `:8787`; at startup WARN when BaseURL is localhost/127.0.0.1/::1 and its port differs from the listen port. Move env reads that live outside internal/config into it (SUPERMETRY_E2E_LOGIN_LIMIT, SUPERMETRY_INGEST_DIAG, SUPERMETRY_REFERRER_SPAM_FILE in cmd/supermetry/serve.go, SUPERMETRY_TOMBSTONE_POLL in internal/profiletombstone/store.go, the routehits env var). Put E2E_LOGIN_LIMIT and routehits behind an `e2e` build tag if the Makefile/playwright targets can build with it; otherwise log a loud WARN when set. Also: `make dev` must rebuild web/dist when web sources are newer than web/dist/index.html (today it reuses a stale UI build forever).
2. Ingest (verified bug): `internal/writer/writer.go:355-366` retryOperation retries every error forever; a single event goroutine serves all sites, so a permanently failing batch (e.g. NUL "\u0000" in prop values, which Postgres rejects in jsonb; payload passes them through) wedges ingest for every tenant until the 65,536 queue fills. Fix: (a) sanitize at ingest: strip NUL and invalid UTF-8 from every string reaching the DB; (b) classify errors: transient (connection errors, SQLSTATE class 08, 40001, 40P01, 53xxx, 57P0x, attempt deadline) → existing backoff; permanent (class 22, 23, 42…) → bisect the batch, write good rows, drop+count bad rows with a structured WARN (no PII values); same for the sessions flush; (c) counters for poison-dropped, queue-full-dropped and shutdown-abandoned rows exposed where writer/ingest stats or /metrics already live (internal/dropstats, internal/health); log abandoned count at shutdown.
3. Tests: config default + mismatch warning; a regression test proving a poison row no longer stalls later batches (real Postgres harness the package uses); unit tests for classification and bisection; NUL sanitising.
